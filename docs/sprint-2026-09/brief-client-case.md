# Бриф: подтверждённый кейс клиента (для /cases, /pepperoni или /kontraktnoe-proizvodstvo)

Сейчас `/cases` называет клиентов («Aslam» для АО «ОМПК», «Татнефть», «СМАРТЕН») без
документов и разрешений в репозитории. До подтверждения эти имена нельзя переносить на
коммерческие страницы как доказательство. Нужен один кейс, который можно защитить.

## Кандидаты (выбирают продажи)
1. Private label «Aslam» — если есть договор и письменное согласие ОМПК на упоминание.
2. Сеть АЗС (хот-доги) — если есть объёмы за период и согласие на публикацию.
3. Пиццерия/сеть на пепперони KD-013 — самый нужный кейс для `/pepperoni`.

## Что собрать (продажи + клиент)
| Пункт | Есть / нет | Где лежит |
|---|---|---|
| Согласие клиента на упоминание (письмо/email) | | |
| Задача клиента своими словами (1–3 предложения) | | |
| Что поставляли: SKU, объём/мес, период | | |
| Что изменилось у клиента (факт, не оценка: срок, брак, экономия) | | |
| Цитата контактного лица + должность (утверждённая им) | | |
| Фото продукта у клиента / на полке (с разрешением) | | |
| Документы: спецификация, этикетка СТМ (можно фрагмент) | | |

## Формат публикации
- 400–700 слов, структура: задача → что предложили (SKU, условия) → результат в цифрах → цитата → следующий шаг для читателя.
- RU + EN. Никаких «крупнейший», «лидер» — только проверяемые числа и названия с согласия.
- Ссылка на кейс — из блока «Доказательства» на соответствующей коммерческой странице.

## Что нельзя
- Публиковать без письменного согласия. Придумывать цифры. Использовать логотип клиента без разрешения.

Ответственный: продажи. Срок: недели 3–4. Приёмка: заполненная таблица + согласие в `docs/sprint-2026-09/case-<client>/`.
